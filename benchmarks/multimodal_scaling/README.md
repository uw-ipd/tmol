# TMol multimodal scaling benchmarks

This versioned harness compares two workflows:

1. whole-pose score plus Cartesian-coordinate gradients; and
2. one-repeat FastRelax.

Both speed and peak working memory are measured for protein, protein–ligand,
and protein–DNA/RNA structures across residue count. The comparison includes
PyRosetta 2024.39 CPU, TMol CPU, and TMol H200 CUDA batches 1, 10, 100, and
1000. TMol 0.1.55 is compared with 0.1.46; nucleic-acid historical results use
0.1.47 because 0.1.46 cannot represent that modality.

The final deliverables are exactly two composite figures (each emitted as PDF,
SVG, and PNG):

- `figures/multimodal-workloads-speed.*`
- `figures/multimodal-workloads-memory.*`

Each figure has modality in columns and workflow in rows. Color identifies the
engine/device/batch series; solid and dashed lines distinguish current and
historical TMol.

## Measurement contract

- Speed is structures per second. Score-gradient points are medians of seven
  synchronized intervals after five warmups. FastRelax is a complete native
  one-repeat workflow and has one fixed-seed observation per matrix point.
- CPU memory is process peak resident set size from a fresh process for every
  point. GPU memory is peak bytes allocated by PyTorch's CUDA allocator after
  its peak counter is reset, including pose/scorer setup and the workflow.
- Pose loading, scorer rendering, and first-use compilation are excluded from
  steady-state speed, but included in the working-memory measurement.
- Existing nonempty JSON records are skipped. Failed, unsupported, integer-
  overflow, timeout, and out-of-memory points remain explicit records.
- TMol 0.1.55 CUDA score-gradient runs retain eager and graph measurements;
  plotting selects the faster valid fixed-shape execution for speed and uses
  that same selected observation for memory.

## Expanded corpus

`src/select_rcsb_candidates.py` freezes 384 checksum-ready RCSB candidates per
modality using a stable, size-stratified selection. Dataset preparation targets
128 successful structures per modality, or 384 structures total, spanning
roughly 30–1,500 polymer residues.

Protein and protein–DNA/RNA inputs are diverse RCSB structures conservatively
cleaned by PyRosetta. The performance-only protein–ligand scaling corpus grafts
one of nine already validated TMol/PyRosetta ligand fixtures onto each diverse
protein backbone. This avoids treating autogenerated ligand chemistry as
ground truth while varying protein size and ligand chemistry reproducibly.
Every source, cleaned structure, and ligand template is checksum recorded.

## Reproduction

The harness worktree is
`/mnt/home/kdidi/projects/tmol-multimodal-benchmark`; large run data lives under
`/mnt/data/kdidi/tmol-multimodal-scale`. Detached source worktrees for 0.1.46,
0.1.47, and 0.1.55 are under `/mnt/home/kdidi/tmol-paper-sources`.

From `benchmarks/multimodal_scaling`:

```bash
export TMOL_BENCH_ROOT=/mnt/data/kdidi/tmol-multimodal-scale
export TMOL_BENCH_HARNESS=$PWD

mkdir -p "$TMOL_BENCH_ROOT"/{logs,metadata}
cp metadata/{benchmark_spec.json,rcsb_candidates.json} \
  "$TMOL_BENCH_ROOT/metadata/"

prep=$(sbatch --parsable --array=0-2 slurm/prepare_expanded_data.sh)
merge=$(sbatch --parsable --dependency=afterok:${prep} \
  slurm/merge_expanded_data.sh)
```

After the merge job completes, submit score-gradient first. The submitter splits
the task tables into arrays no larger than the site's 1,001-element limit:

```bash
TMOL_BENCH_ROOT="$TMOL_BENCH_ROOT" \
python3 src/submit_task_matrix.py --protocols score_gradient

# If the scheduler's per-user submission cap interrupts a wave, use the exact
# device and offset printed by the submitter, for example:
TMOL_BENCH_ROOT="$TMOL_BENCH_ROOT" \
python3 src/submit_task_matrix.py --protocols score_gradient --devices cuda \
  --start-offset 1800

# Submit after score-gradient arrays drain, to stay below the user job limit.
TMOL_BENCH_ROOT="$TMOL_BENCH_ROOT" \
python3 src/submit_task_matrix.py --protocols fastrelax
```

Regenerate the two composite figures and integrity report with:

```bash
TMOL_BENCH_ROOT="$TMOL_BENCH_ROOT" sbatch slurm/plot_existing.sh
```

The raw JSON files are the durable measurements; summary CSVs and figures are
fully derived and can be regenerated at any time.

For a large matrix, `src/feed_scheduler.py` can feed ordered table segments as
capacity becomes available under the 3,000-job QOS cap and schedule the final
report with `afterany` dependencies. Its progress is atomically recorded in
`metadata/scheduler_feeder_state.json`; `slurm/feed_remaining.sh` is the
resource-light Slurm wrapper. Pass already submitted array IDs with repeated
`--dependency-job` arguments so the finalizer waits for the complete run.
