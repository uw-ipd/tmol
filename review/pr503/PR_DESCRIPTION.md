Generalized chemistry currently mixes residue-instance identity, sampler ownership and mutable parameter caches in ways that can change scores or conformers when poses, databases or samplers are reused. This follow-up fixes those contracts, enforces explicit allocation budgets, repairs mirror/grid behavior, and reduces repeated host/device setup and unbounded retention. It targets `dimaio/noncanonicals_through_ligand_pipeline`, including the updates through `0593a93b07d80b0302383163d2d98c78e315ab98`.

This is a review-driven follow-up to #503. Some problems are inherited code assumptions exposed by generalized chemistry; the detailed review distinguishes those from defects introduced by #503. Corrections already made upstream are credited below. Generated force-field files were reviewed through their generators, schema, provenance and executable checks; this is not an independent scientific refit.

## AtomWorks reuse and companion work

The tmol side consumes a completed AtomArray and its declared chemistry annotations, so AtomWorks parsing can supply unresolved atoms and connectivity without a second structure parse. The local corpus below exercises both this route and tmol's reader on the same normalized files. Tmol still owns parameter generation and native numerical scoring.

The current companion is [AtomWorks #349](https://github.com/baker-laboratory/atomworks-dev/pull/349), based on latest `dev` `59afb1e2` and pinned at `774056c7`. This tmol branch makes AtomWorks a **core dependency** and removes its duplicate Dimorphite engine, carboxylate/radical-O repairs, bond-map/restoration code, and authored CIF category parser. It preserves tmol's scientific rule data and force-field-specific normalization. The compatibility extra `tmol[atomworks]` remains empty. Native tensor/GPU histidine resolution stays in tmol and is directly compared against the shared selector.

**Dependency publication requirement:** the draft uses an immutable authenticated Git/SSH dependency on the AtomWorks companion commit. It requires access to `baker-laboratory/atomworks-dev` and is not yet a public-release dependency; replace it with the released version containing #349 before public package publication. Core dependency resolution via `uv pip compile` succeeds and selects Biotite 1.6.0; this is not a clean install/test of every extra. The earlier AtomWorks 2.2.1 compatibility matrix applies to pre-sharing commit `01159dd7a`, not this new required API. The native CIF reader remains the default while author/label, leaving-group and full atom-provenance policy is settled.

The complete protonation audit found rule/data differences, incomplete older local HIS postprocessing, atom reordering/property loss through reactions, metadata loss through fallback SMILES, and loss of input HIS H at the tmol adapter. All are addressed under an explicit compatibility policy. **774 ordered mapped-state comparisons match** the prior tmol engine; using AtomWorks' different default inventory instead produces five differences. AtomWorks chemistry tests: **180 passed**, with **74 affected tests passing after final review**. tmol direct native/AW-HIS and reader/CIF selection: **23 passed**. Final targeted checks pass **46 tmol tests and 34 AtomWorks histidine tests**; these overlap the earlier selections. The older local suite's 11 passing helper tests did not establish correct integration. The legacy vendor self-test was also run on latest AW dev, pre-sharing tmol and the shared engine: all three stop at the same secondary-aniline/protective-rule assertion; its expectations were not changed. [Detailed policy, anchored comments and artifacts](https://github.com/kierandidi/tmol/blob/review/pr503-chemistry-efficiency/review/pr503/PROTONATION_AUDIT.md).

Against the converter in latest AtomWorks dev, isolated 20-/200-atom inputs improve 0.230 → 0.123 ms and 1.812 → 0.986 ms. A 3,000-atom/32-unused-annotation case improves 58.920 → 14.116 ms and Python-traced peak 49.261 → 0.176 MB. These are nine-repeat warm microbenchmarks with equal output chemistry/coordinates, not whole-workflow speedups or total native-memory measurements. Historical old-companion measurements remain in [ATOMWORKS.md](https://github.com/kierandidi/tmol/blob/review/pr503-chemistry-efficiency/review/pr503/ATOMWORKS.md).

The proposed end state is **two frontends sharing one preparation core**: AtomWorks for file parsing/topology metadata, and direct Torch coordinates through prepared named layouts or explicit atom mappings. Atom14, atom37 and backbone4 become presets; OpenFold/RoseTTAFold wrappers delegate and are then deprecated. Preserve RF2-supplied hydrogens and coordinate gradients, and keep discrete sidechain packing an explicit policy. PR #380 should become a thin backbone4 adapter plus shared completion tests. This generic API and removal of old entry points are **not implemented in this PR**. See [INPUT_CONTRACT.md](https://github.com/kierandidi/tmol/blob/review/pr503-chemistry-efficiency/review/pr503/INPUT_CONTRACT.md) for the worktree comparison, encoding checks, gradient probe and anchored #380 review comments.
